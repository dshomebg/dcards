# Задание: Платформа за NFC визитки (магазин + профили)

Версия 1.0 · 13.09.2026

## 1. Цел

Един Next.js проект, който:

1. Продава физически NFC визитки (магазин)
2. Хоства публичните профили, към които сочат чиповете
3. Дава на клиентите dashboard за редакция на профили и управление на карти

## 2. Взети решения

| Въпрос                | Решение                                                                          |
| --------------------- | -------------------------------------------------------------------------------- |
| Профили на потребител | Няколко, през организации                                                        |
| Магазин               | В същия Next.js проект                                                           |
| Вход                  | Имейл + парола                                                                   |
| Монетизация           | Free + Pro (Pro се развива по-късно, само основата сега)                         |
| Дизайн на картата     | Клиентът качва лого/име, дизайнът се нарежда ръчно (без онлайн конструктор в v1) |
| Чип                   | Записва се веднъж с постоянен URL `/c/{card_id}`; никога не се презаписва        |

Извод: всичко е в един монолит, но платформата и магазинът са отделни модули в кода.

## 3. Стек

| Слой        | Технология                                                         |
| ----------- | ------------------------------------------------------------------ |
| Framework   | Next.js 15, App Router, TypeScript                                 |
| DB          | PostgreSQL + Drizzle ORM                                           |
| Auth        | Auth.js v5, credentials provider, bcrypt, сесии в DB               |
| Storage     | S3-съвместимо (MinIO на Hetzner) за снимки/лога                    |
| Изображения | sharp – ресайз до 512px профилна снимка, 256px лого, WebP          |
| QR          | `qrcode` (сървърно, SVG/PNG)                                       |
| vCard       | ръчно генериран `.vcf` (vCard 3.0)                                 |
| Имейли      | Resend или собствен SMTP; шаблони с react-email                    |
| Плащания    | наложен платеж + картово плащане (myPOS или Stripe – за уточнение) |
| Доставка    | Еконт / Спиди API за товарителници (v1 – ръчно, API във v2)        |
| Deploy      | Docker на Hetzner, Postgres в контейнер, Caddy/Nginx               |

## 4. Домейни

| Домейн              | Предназначение                     |
| ------------------- | ---------------------------------- |
| `brand.bg`          | Магазин, dashboard, админ          |
| `xxx.link` (кратък) | Само публични профили и card URL-и |

- `xxx.link/c/{card_id}` – URL записан в чипа
- `xxx.link/{slug}` – публичен профил

Блокер: краткият домейн се печата на карти завинаги – трябва да е купен и подновяван дългосрочно преди първата партида.

## 5. Модел на данните

### 5.1 Потребители и организации

| Таблица       | Полета                                                                                         |
| ------------- | ---------------------------------------------------------------------------------------------- |
| users         | id, email (unique), password_hash, name, email_verified_at, created_at                         |
| organizations | id, name, type (personal/company), plan (free/pro), plan_expires_at, owner_user_id, created_at |
| org_members   | org_id, user_id, role (owner/editor), created_at                                               |

- При регистрация автоматично се създава organization с type=personal и потребителят става owner
- Един user може да е член на много организации

### 5.2 Профили

| Таблица       | Полета                                                                                                                                                                                   |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| profiles      | id, org_id, slug (unique, 3–30 символа), first_name, last_name, title, company, bio, photo_key, logo_key, theme (json: preset, primary_color, layout), is_public, created_at, updated_at |
| profile_links | id, profile_id, type, label, value, sort_order, is_visible                                                                                                                               |

Типове линкове (`type`): phone, email, website, linkedin, facebook, instagram, tiktok, youtube, whatsapp, viber, telegram, address, custom

Извод: полетата за контакт са редове в `profile_links`, не колони – нов тип линк не иска миграция.

### 5.3 Карти

| Таблица      | Полета                                                                                                                                                                                                   |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| card_batches | id, name, quantity, created_at, created_by                                                                                                                                                               |
| cards        | id (публичен, 6–8 символа, base32 без 0/O/1/I), batch_id, activation_code (6 цифри, unique в партидата), status, org_id (nullable), profile_id (nullable), order_id (nullable), written_at, activated_at |

Статуси: `blank` → `written` → `assigned` (в поръчка, неактивирана) → `active` → `disabled`

- `org_id` без `profile_id` = картата е в организацията, но неразпределена
- Картата може да се пренасочи към друг профил в същата организация без промяна на чипа

### 5.4 Статистика

| Таблица | Полета                                                                                           |
| ------- | ------------------------------------------------------------------------------------------------ |
| scans   | id, card_id, profile_id, scanned_at, source (nfc/qr/direct), device (ios/android/other), country |

Без IP, без user-agent в суров вид – само агрегирани данни. Достатъчно за GDPR без съгласие.

### 5.5 Магазин

| Таблица          | Полета                                                                                                                                                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| products         | id, slug, name, description, material (pvc/metal/wood), base_price, is_active, images (json)                                                                                                                         |
| product_variants | id, product_id, name (цвят/финиш), price_delta, sku, stock                                                                                                                                                           |
| orders           | id, number, user_id (nullable – гост), org_id (nullable), status, customer (json: име, тел, имейл), shipping (json: адрес, куриер, офис), payment_method, payment_status, subtotal, shipping_cost, total, created_at |
| order_items      | id, order_id, variant_id, quantity, unit_price, personalization (json: name, title, logo_key, notes)                                                                                                                 |

Статуси на поръчка: `new` → `paid` (или `cod`) → `in_production` → `shipped` → `delivered` / `cancelled`

## 6. Потоци

### 6.1 Активация през чипа

```
Телефон отваря xxx.link/c/{card_id}
  ├─ status = active     → 302 → xxx.link/{slug} (+ запис в scans)
  ├─ status = written/assigned → страница "Активирай картата"
  │     ├─ има акаунт → вход → избор на организация → избор/създаване на профил → card.status=active
  │     └─ няма акаунт → регистрация (създава org) → създаване на профил → card.status=active
  ├─ status = disabled   → "Картата не е активна"
  └─ не съществува       → 404
```

- След активация чипът винаги води към профила. Смяната на профила се прави от dashboard-а.
- Ако картата има `org_id` (купена от логнат клиент), активацията изисква вход в същата организация – защита срещу чужда активация.

### 6.2 Активация с код (без NFC)

Dashboard → „Добави карта“ → въвежда `card_id` + `activation_code` (и двете са отпечатани на гърба). Съвпадение → картата влиза в организацията като неразпределена.

### 6.3 Поръчка

1. Клиент избира продукт + вариант, попълва персонализация (име, длъжност, качва лого)
2. Checkout: гост или логнат; адрес; куриер; плащане
3. Логнат клиент: поръчката се връзва към текущата организация
4. Имейл потвърждение

### 6.4 Изпълнение (админ)

1. Админ отваря поръчката, вижда персонализацията, сваля логото
2. Избира N карти от партида със status=written → status=assigned, order_id се записва; ако поръчката има org_id → и org_id
3. Печат/производство извън системата
4. Маркира „изпратена“, въвежда товарителница → имейл до клиента с номера на пратката и инструкция за активация

### 6.5 Партиди карти (админ)

1. Създава партида с брой
2. Системата генерира card_id + activation_code за всяка
3. Експорт CSV: `card_id, url, activation_code` – за записване на чиповете (NFC Tools / писач) и за печат на гърба
4. Записаните се маркират `written` (ръчно или масово)

## 7. Екрани

### 7.1 Публични

| Път                                     | Съдържание                                |
| --------------------------------------- | ----------------------------------------- |
| `/`                                     | Landing на магазина, продукти, как работи |
| `/products`, `/products/{slug}`         | Каталог и продукт с персонализация        |
| `/cart`, `/checkout`, `/order/{number}` | Стандартен поток                          |
| `xxx.link/{slug}`                       | Публичен профил                           |
| `xxx.link/c/{id}`                       | Card router (виж 6.1)                     |

Публичен профил – изисквания:

- SSR, кеш с revalidate по `profiles.updated_at`
- Без клиентски JS освен за бутоните; LCP < 1.5s на мобилен
- Бутон „Запази контакт“ → `/api/vcard/{slug}` → `.vcf` с име, длъжност, фирма, телефони, имейл, сайт, снимка (base64)
- Бутон „Сподели“ (Web Share API) + QR
- Линковете отварят native приложенията (tel:, mailto:, whatsapp://, viber://)
- Open Graph за споделяне в чат

### 7.2 Dashboard (клиент)

| Път                  | Съдържание                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| `/app`               | Списък профили на текущата организация                                                           |
| `/app/profiles/{id}` | Редактор: полета, линкове (drag-and-drop ред), снимка, лого, тема; живо превю в рамка на телефон |
| `/app/cards`         | Карти: статус, към кой профил, пренасочване, деактивация, добавяне с код                         |
| `/app/analytics`     | Сканирания по ден/карта/профил (Pro)                                                             |
| `/app/org`           | Членове, покани по имейл, смяна на организация                                                   |
| `/app/orders`        | История на поръчките                                                                             |
| `/app/settings`      | Имейл, парола                                                                                    |

### 7.3 Админ

| Път                           | Съдържание                                                              |
| ----------------------------- | ----------------------------------------------------------------------- |
| `/admin/orders`               | Списък, филтри по статус, детайл, присвояване на карти, смяна на статус |
| `/admin/batches`              | Партиди, генериране, CSV експорт, маркиране „записани“                  |
| `/admin/cards`                | Търсене по card_id, ръчно свързване/откачане                            |
| `/admin/users`, `/admin/orgs` | Преглед, смяна на план, дата на изтичане                                |
| `/admin/products`             | CRUD продукти и варианти                                                |

Роля admin – флаг `is_admin` в users.

## 8. Free vs Pro

| Функция                               | Free     | Pro                              |
| ------------------------------------- | -------- | -------------------------------- |
| Профили в организация                 | 1        | без лимит                        |
| Линкове на профил                     | 6        | без лимит                        |
| Теми                                  | 3 готови | + собствени цветове, лого на фон |
| Статистика                            | –        | да                               |
| Членове в организация                 | 1        | без лимит                        |
| Премахване на брандинг на платформата | –        | да                               |

Реализация в v1: `plan` + `plan_expires_at` в organizations и helper `can(org, feature)`. Всяка Pro проверка минава през него. Без billing – планът се сменя от админа. Stripe subscriptions във v2 пишат в същите две полета.

## 10. Етапи

| Етап | Обхват                                                              | Оценка    |
| ---- | ------------------------------------------------------------------- | --------- |
| 1    | Auth, организации, профили, публична страница, vCard, QR            | 2 седмици |

| 3    | Магазин: продукти, количка, checkout, наложен платеж, админ поръчки | 2 седмици |
| 4    | Картово плащане, имейли, статистика, Pro gating                     | 1 седмица |

Извод: след етап 2 платформата вече може да обслужва карти, продадени и извън сайта – магазинът не е блокер за старт.

## 11. Блокери

- Кратък домейн – трябва да е решен преди първата партида (печата се на картите)
- Платежен доставчик – myPOS (BG, наложен + карта) или Stripe (по-лесна интеграция, без наложен) – за уточнение
- Дълготрайност – раздадените карти работят само докато платформата е онлайн; нужен е план за backup и минимум 5 години поддръжка
- Логата на клиентите идват в произволни формати (jpg, png, pdf, ai) – в v1 се приема всичко, оправя се ръчно при производство
- Slug-ове – резервирани думи (admin, app, api, c, login…) и защита от squatting на фирмени имена
