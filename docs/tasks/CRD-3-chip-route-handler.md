## Какво и защо

`?s=nfc` оставаше в адресната лента след чип и копираният адрес не се броеше като „линк" (ANL-2).
Само route handler може да сложи cookie на redirect-а: `/c/{id}` → запис `nfc` → 307 към чист
`/{slug}` + `scan_seen={slug}` (30 s, HttpOnly, path=`/{slug}`); `/{slug}` пропуска записа, когато
cookie-то съвпада със slug-а. Служебните екрани (активация, неактивна, несвързана) са на
`/c/{id}/activate`; `next` след вход остава `/c/{id}` и минава през handler-а.

## Приемни критерии (проверени)

- [x] Чип → 1 `nfc`, следващото отваряне на профила в същия браузър до 30 s не е „линк".
- [x] Копиран чист адрес в друг браузър → `direct`. `?s=nfc` без cookie → `direct`.
- [x] `written` карта → `/c/{id}/activate` (Вход/Регистрация); активна на `/activate` → обратно.
- [x] Невалиден/липсващ id → 404; `Location` е по `APP_URL`, не по `Host`.
